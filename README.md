JevAlt is a set of three open-weights 4B decision models: Deem-4B for English, Karar-4B for Turkish and Wähler-4B for German. Give a model a situation and your options, and it returns a calibrated probability for each option through TypeSafe's Jev API (`POST /v1/systemone`), for tasks such as routing support tickets or checking a written policy. The Q4_K_M GGUF builds run on a CPU in about 3 GB of RAM. This repo has the `jevalt` server and command line, the training and export code, and links to the weights, the training data and every recorded decision.

---

## Why JevAlt

Small decision models trip over planted instructions, long policies, negations and missing facts; JevAlt trains on each one and publishes the results.

## Features

**Models**

- Deem-4B (English), Karar-4B (Turkish) and Wähler-4B (German), each with a GGUF repo holding Q4_K_M, Q5_K_M and Q8_0 builds.
- All three start from [Intern-Decision-4B](https://huggingface.co/internlm/Intern-Decision-4B) (Apache-2.0, based on Qwen3.5-4B) and were trained on decisions written in English, Turkish and German.
- Calibrated per question type and language, with conformal answer sets fitted on held-out decisions.

**Answers**

- Question types: `choice` (up to 62 options), `score` (2 to 10 ordered levels) and `noul` (the probability of yes).
- Optional extensions: `abstain: true` adds an `unknown` option, `coverage` returns an answer set at 80, 90 or 95%, and `reasoning` (off, on or auto) writes a short trace of at most 256 tokens before the decision.
- Choice and Score answers carry a probability per option and a confidence value, a Noul answer is the probability of yes, and one request can ask several questions.

**Server and command line**

- `jevalt serve` runs a GGUF build with llama.cpp or the full weights with Transformers (`--backend hf`), and `jevalt ask` answers one request without a server.
- Routes `/health`, `/v1/models` and `POST /v1/systemone`. The server binds to 127.0.0.1 by default and asks for a bearer token when `JEVALT_API_KEY` is set.
- GGUF files load without memory mapping by default, which keeps Q4_K_M at about 3 GB; `--mmap` and `--no-repack` change that.

**Training and evaluation**

- [training/](training/) holds the data mix, LoRA training, model cards, Transformers and HTTP evaluation, GGUF export with parity checks, and the base-checkpoint bake-off.
- Training data in [jevalt-data](https://huggingface.co/datasets/mertkayacs/jevalt-data), every result file and recorded decision in [jevalt-bench](https://huggingface.co/datasets/mertkayacs/jevalt-bench).

## Quick start

With Python 3.11 or newer, install the package with the server and llama.cpp extras, then start a server with the English model:

```sh
pip install "jevalt[serve,gguf] @ git+https://github.com/mertkayacs/jevalt"
jevalt serve
```

The first run downloads Deem-4B's Q4_K_M build (2.71 GB) from Hugging Face and listens on `http://127.0.0.1:8000`. In another terminal, send a support ticket:

```sh
curl -s http://127.0.0.1:8000/v1/systemone -H 'Content-Type: application/json' -d '{
  "state": "I was charged twice for March. Please refund the duplicate.",
  "questions": {"team": {"type": "choice",
    "instructions": "Which team should handle this ticket?",
    "criteria": {"billing": "payments, refunds", "technical": "bugs, outages",
      "sales": "prices, contracts"}}}}'
```

The answer comes back under `answers.team` with the chosen option, a probability for each option and a confidence value. For Turkish or German, serve the matching model:

```sh
jevalt serve --model mertkayacs/Karar-4B-GGUF --file Karar-4B-Q4_K_M.gguf
jevalt serve --model mertkayacs/Wahler-4B-GGUF --file Wahler-4B-Q4_K_M.gguf
```

To answer one request without a server, run `jevalt ask request.json`. On a GPU, install the `hf` extra and run `jevalt serve --backend hf --model mertkayacs/Deem-4B`. [Run locally](https://mertkayacs.github.io/jevalt/local/) covers memory, speed and TypeSafe's Python SDK.

### Requirements

- Python 3.11 or newer. CI runs the tests on 3.11 and 3.13.
- About 3 GB of free RAM for a Q4_K_M build: each one peaked at 3.03 to 3.04 GB with a 4k context. A GPU is optional.
- 2.71 GB of disk per Q4_K_M file. The Q5_K_M (3.08 GB) and Q8_0 (4.48 GB) builds sit in the same Hugging Face repos.
- Extras: `serve` adds FastAPI and Uvicorn, `gguf` adds llama-cpp-python, `hf` adds PyTorch and Transformers.

## JevAlt vs Kev-4B and Laya

Kev-4B and Laya are other models that choose from supplied options. Each model answered the same held-out items through the same client, as its makers ship it.

|  | JevAlt | Kev-4B | Laya |
|---|---|---|---|
| English held-out decisions | **Deem-4B 94.7%** | 84.7% | 55.3% |
| Turkish held-out decisions | **Karar-4B 96.8%** | 87.1% | 32.7% |
| German held-out decisions | **Wähler-4B 92.0%** | 81.1% | 47.2% |
| typed-decisions | **Deem-4B 81.0%** | 67.0% | 36.1% |
| German news topics (10kGNAD) | Wähler-4B 62.5% | **65.3%** | 59.5% |
| German sentiment (GermEval 2017) | Wähler-4B 64.3% | **65.3%** | 45.0% |
| Probability error on English decisions (Brier, lower is better) | **Deem-4B 0.091** | 0.256 | 0.581 |
| Answers flipped by a planted line (lower is better) | **Deem-4B 14.0%** | 36.0% | 42.0% |
| Accuracy points lost to 600 words of unrelated text (lower is better) | Deem-4B 17.4 | **5.4** | 10.4 |
| Answers unknown when the deciding fact is missing | yes, 9 of 11 | no | no |

<sub>Checked against [comparison.json](https://huggingface.co/datasets/mertkayacs/jevalt-bench/blob/main/results/comparison/comparison.json) in jevalt-bench (published 1 October 2026) in November 2026. Kev-4B is jaredpalmer/kev-4b r10 and Laya is laya-serve 0.3.22. The held-out rows come from JevAlt's own data pipeline, which favours JevAlt. The recorded decisions are in the same folder.</sub>

| Wähler-4B | German | [mertkayacs/Wahler-4B](https://huggingface.co/mertkayacs/Wahler-4B) | [Wahler-4B-GGUF](https://huggingface.co/mertkayacs/Wahler-4B-GGUF) | 122 of 130 right |

The live tests sent each model 130 requests in its own language across five cases: planted instructions, long policies, negations, missing facts and casual messages. Every request and answer is in [results/tested](https://huggingface.co/datasets/mertkayacs/jevalt-bench/tree/main/results/tested).

Training used rank-32 LoRA on the bf16 weights of Intern-Decision-4B on one A100 80 GB: one shared epoch over 17,363 English, Turkish and German rows, then one epoch per language (7,783 rows for Deem-4B, 5,982 for Karar-4B, 5,384 for Wähler-4B). The released models used about 2.7 A100 hours, and the whole project, labeling included, cost 32.2 USD.

## FAQ

<details>
<summary><b>What is a decision model?</b></summary>

A decision model reads a situation, chooses from options you supply and returns a probability for each one. JevAlt has one 4B model per language, and all three take the same request format.
</details>

<details>
<summary><b>Which model should I use?</b></summary>

Deem-4B for English, Karar-4B for Turkish and Wähler-4B for German. `jevalt serve` starts Deem-4B unless you pass another GGUF repo and file.
</details>

<details>
<summary><b>Can I run JevAlt without a GPU?</b></summary>

Yes. The Q4_K_M builds peak at about 3 GB of RAM on a CPU, measured on an 8-vCPU Hugging Face machine with a 4k context and llama.cpp. Their chosen option matched the full-precision model on 95.2% to 97.5% of parity-test decisions. Memory and speed depend on your machine.
</details>

<details>
<summary><b>Does it work with my Jev client?</b></summary>

The server implements `POST /v1/systemone`, so a request that works with Jev works here. Point your client's base URL at the local server. The extensions are optional, and without them the response has Jev's shape.
</details>

<details>
<summary><b>How well does it resist planted instructions?</b></summary>

On the JevOss probe, the share of answers flipped by a planted line is 14.0% for Deem-4B, 19.0% for Karar-4B and 17.5% for Wähler-4B, against 36.0% for Kev-4B. The probe counts the answers that picked the option the planted line asked for. The target was under 5%, so treat the text you send as data and keep authorization decisions in your own code.
</details>

<details>
<summary><b>What are the known limits?</b></summary>

Probabilities are calibrated on held-out project data, so refit them on your own data with [JevOss](https://github.com/mertkayacs/jevoss) before you set thresholds. Long, noisy text and date questions remain weak spots: with 600 words of unrelated text in front, Deem-4B loses 17.4 points, and dates stay at 71.3% on held-out rows.
</details>

<details>
<summary><b>How was it trained, and what did it cost?</b></summary>

With rank-32 LoRA on Intern-Decision-4B on one A100 80 GB. Open-weight models wrote the scenario rows directly in each language, two teacher models from other labs labelled them, and public datasets and programmatic fix sets filled in the rest. The released models took about 2.7 A100 hours, and the whole project cost 32.2 USD.
</details>

<details>
<summary><b>Can I see it work without installing anything?</b></summary>

[Emberwick](https://emberwick.mertkayacs.com/?utm_source=github&utm_medium=readme&utm_campaign=jevalt-repo&utm_content=faq-emberwick) is a village game in the browser where each villager's next move comes from the models' recorded answers. Click a villager to open the decision panel with the leading options and their probabilities, in English, Turkish or German.
</details>

```sh
git clone https://github.com/mertkayacs/jevalt && cd jevalt
pip install -e ".[dev,serve,data]" numpy
pytest -q
```

CI runs the same tests on Python 3.11 and 3.13. The scripts in [training/](training/) are the ones that produced the release: data mix, LoRA training, evaluation and GGUF export. To rebuild the docs site:
